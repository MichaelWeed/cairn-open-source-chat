## Observations

* **Citation precision (33%) is a corpus-size artifact, not a retrieval bug.**
  With only 3 documents in `eval/corpus/` and `retrieval_top_k=4` (clamped to
  3), every query retrieves the entire corpus — precision is mechanically
  capped at 1/3 regardless of query relevance. This will look completely
  different on a real, larger corpus; it's flagged here so it isn't
  mistaken for a defect in `retrieve_chunks()`.
* **The mechanical refusal gate (task 2.5) didn't catch
  `unanswerable-competitor`, but the model declined anyway.** All 3
  documents fell within `retrieval_max_distance=1.2` for that query — same
  corpus-size effect as above — so `should_refuse()` returned `False` and
  the provider was called. The model still answered correctly ("I don't
  have access to competitor information...") because the system prompt's
  own instruction ("if `<retrieved-context>` does not contain the answer,
  say you don't have enough information rather than guessing") caught what
  the distance threshold missed. Worth knowing: on a small corpus, the
  retrieval-confidence gate and the prompt-level instruction are both
  doing real work, not just the gate — don't assume the gate alone is
  sufficient before task 4.4's adversarial suite exists to pressure-test
  this further.
